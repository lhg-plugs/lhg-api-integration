# /lhg-api-integration:rateplan —— 限流与重试策略设计

用户输入在 `$ARGUMENTS` 中：`"<API 名称>" [--qps 数字]`。`--qps` 是你期望的调用频率（缺省按文档限流档位反推）。

## 流程（加载 lhg-api-retry 全程指导）

### 1. 先读限流档位
从文档找（按 lhg-api-retry 第 2 节）：
- 限流维度：按 key / 按 IP / 按账号？
- 配额：每分钟/每小时多少次？响应头 `X-RateLimit-Limit/Remaining/Reset` 有没有？
- 超限行为：429 + `Retry-After`？还是直接封 key？

### 2. 输出策略卡
```markdown
## 限流重试策略卡：<API>
- 配额：<X 次/分钟>（来源：文档第 Y 节）
- 本地节流：每两次请求间隔 ≥ <N>ms（留 20% 余量，别顶着上限跑）
- 重试：最多 3 次，只重试 超时/网络错/429/5xx；退避 1s→2s→4s + 抖动
- 429：读 Retry-After，按它等；没有则按退避来
- 熔断：连续 5 次 5xx → 停 60s 再试，并告警
- 降级：<读接口可走缓存 / 写接口排队稍后重试>
```

### 3. 落到代码
把策略写成可复用的装饰器/中间件（见 lhg-api-retry 第 5 节模板），不要每个接口手写一遍。

## 硬规则
- 顶着限流上限跑 → 不许，留余量。
- 429 无脑立即重试 → 不许，这是被封 key 最快的方式。
- 重试 4xx 参数错误 → 不许，错了就是错了，重试没用。
