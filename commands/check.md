# /lhg-api-integration:check —— 对接代码体检

用户输入在 `$ARGUMENTS` 中：`[对接代码目录] [--fix]`。目录缺省为当前项目根目录。

## 流程（加载 lhg-api-ship 第 3 节全程指导）

### 1. 跑脚本
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/api_audit.py --target <目录> --format text
```
记下 blocker / warning / nit 的数量与明细（含文件、行号、规则说明）。

### 2. 分级与修复
- **blocker**（密钥硬编码、无超时、无限重试、空异常吞没、`verify=False`）：逐条修。`--fix` 缺省即自动修（最小改动原则）；修一条用脚本复查一条。
- 修不掉的（如需要用户提供真实密钥）→ 列入「需人工处理」，不许为清零改规则。
- **warning**（无重试、无 429 处理、无分页、错误码不分级）：修掉或写豁免理由（+有效期）；**nit**：顺手修。

### 3. 人工复核（脚本抓不到的）
- 凭证是不是真的全走了环境变量（搜一遍 `sk-` / `Bearer ey` 之类的真值残留）？
- 重试策略里有没有「不该重试的也重试」（如 400 参数错误进重试）？
- 分页循环有没有终止条件（`has_more` / `next_cursor` 判空）？
- 错误提示给不给人看（直接把 API 原始报错甩给用户？脱敏了吗）？

### 4. 输出报告
按 lhg-api-ship 第 6 节模板输出自查报告，结论写清「通过 / 不通过」。

## 硬规则
- 有 blocker 就说「通过」→ 不许。
- 为清零改脚本规则或阈值 → 这是作弊，不许。
